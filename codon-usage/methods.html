DATA · METHODS

How we calculate the tables.

Codon usage tables in Nucleora are computed from primary sequence data, not copied from secondary databases. Every decision in the pipeline is documented here.

Data source

All tables are computed from NCBI RefSeq annotated CDS sequences, fetched via the NCBI Datasets API. We use the *_cds_from_genomic.fna.gz file from each species' reference assembly.

We do not use CDS sequences from Ensembl, UniProt, or third-party codon databases. Using a single, named, versioned source makes the data reproducible and auditable.

RefSeq release numbers and the tally date are recorded alongside every table. If you're comparing across species, you're comparing tables computed with the same pipeline from the same release.

Filtering criteria

CDS sequences are included in the tally if they pass all of the following:

  • Annotated as protein-coding (feature_type=CDS in RefSeq annotation)
  • Length divisible by 3 with no internal stop codons
  • Minimum 100 nt after stripping start and stop codons
  • No ambiguous IUPAC bases (N, R, Y, S, W, K, M, B, D, H, V)
  • Sequence begins with ATG

These filters remove pseudogenes, partial sequences, and annotation errors. The n count on each table reflects how many CDS sequences passed all filters, not the species' total gene count.

Tally method

For each sequence that passes filtering, every codon position is counted (excluding the start ATG and stop codon). Counts are summed across all sequences. Relative synonymous codon usage (RSCU) and per-1000 frequencies are calculated from the raw counts.

The tally is unweighted - each CDS sequence contributes equally regardless of expression level. This is the standard approach for codon optimization context. Expression-weighted tables (using RNA-seq TPM data) are planned for a future release; that document will note the distinction explicitly.

Proxy species policy

For species where RefSeq has fewer than 500 CDS sequences passing filters, Nucleora selects a proxy species and reports it explicitly. The proxy is selected by:

  • Taxonomic distance (closest named relative with ≥ 2,000 CDS sequences)
  • If multiple candidates exist at the same distance, the one with the highest CDS count wins
When a proxy is used, the in-app codon optimization panel shows the proxy species name in amber, the distance metric, and the proxy's n-count. Nucleora never approximates silently.

We do not interpolate, blend, or weight-average across species to produce a "synthetic" table. If the data doesn't exist, we say so and name the closest real table we have.

Update cadence

Tables are re-tallied after each major RefSeq release (approximately every 3 months). The release number and tally date are embedded in every table file distributed with Nucleora. Updates ship as part of the standard application update; no manual data download is required.

Benchmarks we publish

We validate each table against published RSCU values for Human, Mouse, E. coli K-12, and S. cerevisiae. Discrepancies > 5% in any synonymous codon fraction are investigated before the table is released.

Known systematic differences (e.g., from using unweighted vs. expression-weighted tallies) are documented in the release notes. If our table differs from a published value and we can't explain why, we flag the codon and note the discrepancy rather than silently accepting it.

We publish the benchmarks we lose. Transparent method documentation is part of the product.
